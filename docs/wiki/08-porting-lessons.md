## 일반 규칙 (다른 RE 시리즈 공통)

### 이식 점검표 (순서대로)

1. **빌드를 고정합니다.** 실행 파일을 해시하고 이미지 베이스와 빌드 문자열을 기록하며 그 외는 거부합니다. 조사한 모든 파일의 기준 날짜와 해시를 기록합니다.
2. **지도의 GUI 클래스를 찾습니다.** 지도 객체, 방 인스턴스, 스프라이트 클래스와 그 vtable 슬롯을 식별하고 클래스 이름 CRC로 확인합니다. 비슷한 클래스가 여럿이라 잘못된 것을 먼저 후킹하기 쉽습니다.
3. **방 상자를 캡처합니다.** 방마다 스프라이트 상자를 합치고 방이 아닌 작은 스프라이트는 장애물로 둡니다. 뷰를 추정해 허용 오차 안에서만 수용합니다.
4. **배치를 추출합니다.** 배치 표를 엄격하게 파싱하고 게임 자체의 변환을 실행하며 틀린 배율이 실패하는 테스트로 배율을 증명합니다.
5. **플래그 배열과 배치 관리자를 찾습니다.** 조건 규칙, 완료 규칙, 처치 규칙, 난이도 규칙을 쓰고 읽기 가능 검사 없이는 아무것도 읽지 않습니다.
6. **분류를 정합니다.** 고정 순서와 고정 색의 6개 분류, 무기는 핵심 아이템, 인물은 표식 없음, 게임이 이미 표시하는 오브젝트는 건너뜀.
7. **이름과 아이콘을 생성합니다.** 이름은 표시 크기에 가깝게 미리 렌더링하고, 글자 아틀라스 하나와 밉이 있는 아이콘 텍스처 하나를 두며, 32비트 메모리 예산을 확인합니다.
8. **방 이름을 빌드 때 배치합니다.** 방 스프라이트 알파로 극점·지시선·줄바꿈을 계산하고, 빌드를 멈추게 하는 독립 검사를 둡니다.
9. **공용 프레임 모듈을 씁니다**(표식, 계층, 이름, 버린 아이템, 범례, 수치 패널). 계약과 그 변이체를 추가합니다.
10. **후킹하고 Present에서 그립니다.** 페이드 게이트와 세대 래치를 쓰고 장치 상태를 전부 복원합니다.
11. **프레임(크롬)을 측정합니다.** 지원할 해상도의 실게임 스프라이트 덤프에서 측정하고 해상도를 기록합니다.
12. **첫 실게임 시험 전에 네이티브 디스패치 게이트와 변이체를 만들고** 모든 버림 경로에 카운터를 추가합니다.
13. **실게임 순환:** 캡처, 복사, 비교, 변이체 추가, 픽스처 값 추가.
14. **문서:** 처음 쓰는 사용자용 README(설치, 키, 한계)를 내부 기록과 분리하고, 공개 README에 테스트 수, 진행 상황, 검증 이력을 넣지 않습니다.

### 일반 교훈

- 직접 호출한 후크는 아무것도 증명하지 않습니다. 실제 vtable 슬롯으로 도달하고 클래스 정체를 확인합니다.
- 테스트 입력은 필드의 포장된 전체 범위를 덮어야 합니다. 네이티브 코드는 작성자가 켜진 것을 본 적 없는 비트를 마스크할 수 있습니다.
- 데이터를 조용히 버리는 후크 경로는 이후의 모든 실패를 숨깁니다. 경로마다 카운터를 둡니다.
- D3D 출력은 오프라인으로 테스트할 수 없습니다. Present에서 그리고 모든 상태를 복원하며 실게임 점검표를 둡니다.
- 새 게임 뒤만이 아니라 세이브를 불러온 뒤의 상태도 테스트합니다.
- "방 안에 든다"로 증명한 규칙도 틀린 배율을 쓸 수 있습니다. 반드시 실패해야 하는 대조군을 둡니다.
- 제보는 한 분류의 예시로 다루고, 분류 전체를 고치고 테스트합니다.
- 에셋 크기는 검토하지 않은 상수가 아니라 표시되는 가장 큰 크기에서 구합니다. 글자는 표시 크기에 가깝게 미리 렌더링하고, 작은 래스터를 늘리지 않으며, 밉은 프리멀티 채널에서 만들고 모든 레벨에서 가장자리 밝기를 테스트합니다.
- 다른 모드가 타이밍을 바꾸면 시간 창으로는 낡은 그리기를 고칠 수 없습니다. 이벤트에 묶은 래치를 씁니다.
- 다음 캡처가 덮어쓰기 전에 실게임 캡처 파일을 복사하고, 제보마다 해상도와 전체 스크린샷을 요청합니다.
- 설치될 수 있는 빌드마다 고유한 번호를 줍니다.
- 실게임 증상의 원인이 증명되지 않았다면 동작하는 순서나 우회를 유지하고 기록에 그렇게 적으며 해결했다고 주장하지 않습니다.

## RE0 HD Remaster 전용

### 이 프로젝트의 실수와 발견 경로

| 실수 | 발견 경로 | 방지책 |
| --- | --- | --- |
| 인스턴스 후크를 이웃 클래스 슬롯에 설치(`cGUIInstAnimation` 대신 `cGUIInstAnimVariable`) | 실게임: 방이 식별되지 않음. 오프라인 프로브가 후크를 직접 호출해 슬롯이 쓰이지 않았음 | 실제 vtable 슬롯으로만 후크에 도달, CRC로 클래스 정체 확인 |
| 기준 `0xff5`를 10 초과로 거부해 스프라이트가 거부됨 | 로그: 지도 그리기당 `badquad` = 18, `room=0` | 필드의 포장된 전체 범위에 대한 차분 검사. 네이티브는 하위 비트를 마스크함 |
| 후크에서 조용한 버림 | `Diag` 줄이 생기기 전까지 손실이 보고되지 않음 | 모든 버림 경로에 카운터 |
| `EndScene`에서 오버레이가 안 보임 | 실게임: 표시 없음. Present로 옮기자 실게임에서 그려짐 | Present에서 그리기. D3D는 실게임 시험이 필요함을 받아들임 |
| 세이브 로드 후 0이 되는 모드 필드로 표를 판별 | 실게임: 로드 후 획득한 아이템과 열린 문이 계속 표시됨 | 세이브 로드 상태를 테스트하고 행 개수로 표를 판별 |

### 복사하면 안 되는 것

위 표에서 "RE0 전용"으로 분류한 모든 것: 주소와 오프셋(05, 06 페이지), 프레임 사각형 14개, 변환 상수, Leech Hunter 조건 보상, 여러 층 방 13개와 `DROP_FLOOR_Y`, 허브 조합 id 46~51, 아트, 한국어 이름 목록, INI 키.

### 알려진 한계 (분명하게)

1. 프레임 사각형은 2560x1440 스크린샷에서 실측했습니다. 다른 해상도, 화면비, 전환 애니메이션, 스크린샷과 다른 지도는 검증하지 않았습니다. 사각형에 닿는 표식은 통째로 숨겨집니다.
2. 여러 층 방 13개(14, 17, 36, 43, 45, 50, 65, 103, 111, 132, 134, 142, 166)의 버린 아이템은 데이터만으로 층을 정할 수 없습니다. 방 36과 45만 추정 높이 기준을 쓰고 나머지 11개는 맞는 모든 층에 그립니다.
3. 배치 표의 파트너와 시나리오 차이는 추적하지 않았습니다.
4. "본 아이템만 표시" 기능은 보류입니다.
5. 이벤트 내용은 보지 못했습니다. `script_read`는 완료 플래그가 있다는 뜻일 뿐이며, `tr0b` g6가 Stinger라는 식별은 추정입니다.
6. 쉬움/보통/어려움은 표 행 수(647/589/568)로 추정했고 난이도 메뉴와 대조하지 않았습니다.
7. 한국어 방 이름은 프로젝트 번역입니다.
8. Windows와 `re0box`, FusionFix, `RE0.NoUIWait` 외의 모드는 시험하지 않았습니다.
9. 게임 내 확인은 이 위키의 범위 밖입니다(검증 절차는 07 참고).
