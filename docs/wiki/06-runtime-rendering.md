# 06 런타임과 렌더링

[한국어](06-runtime-rendering.md) | [English](06-runtime-rendering.en.md) · [Index](README.md)

경로는 RE0 프로젝트 루트 기준입니다. 인용은 파일과 함수 이름만 적고 줄 번호는 적지 않습니다. 런타임 코드는 `src/runtime/re0_map.c`(이 페이지에서는 `re0_map.c`)이고 판단은 `src/core/frame.c`에 있으며 에뮬레이터와 공유합니다.

## 일반 규칙 (다른 RE 시리즈 공통)

### 역할 분담

- 오버레이가 보여주는 모든 것을 하나의 공용 C 모듈이 판단하고 그리기 연산(사각형, 색, 글리프) 목록을 돌려줍니다. ASI와 에뮬레이터는 그 목록을 칠하기만 합니다. 표식 자격, 투영, 배치 논리를 다른 곳에 중복하지 않습니다.
- ASI는 실행 중인 게임이 필요한 일만 합니다: 후크, 메모리 읽기, 설정, 입력, D3D.

### 게임이 지도를 어디에 그렸는지 알아내기

- 방 상자를 짐작하지 않습니다. 게임의 GUI 클래스를 가상함수 테이블 슬롯에서 후킹합니다: 지도 객체, 방 인스턴스, 스프라이트. 원본을 먼저 호출합니다. 스레드 로컬 컨텍스트는 지도를 그리는 동안에만 존재하므로 다른 GUI의 스프라이트를 방으로 오인하지 않습니다.
- 인스턴스는 소유자가 지금 그려지는 지도이고 id가 표시 중인 지역의 알려진 방과 맞을 때만 받아들입니다. 스프라이트는 텍스처가 있고 알파가 0이 아니며 유효한 사각형일 때만 받아들입니다. 한 방의 스프라이트 상자를 합치고, 방이 아닌 작은 스프라이트 상자는 장애물로 보관합니다(한 변을 제한해 지도 자체의 큰 아트가 장애물이 되지 않게 함).
- 스프라이트의 최종(부모 합성) 행렬과 게임 렌더 인자의 원점·배율로 픽셀 좌표를 얻고, 게임의 렌더 사각형(뷰포트, 바인딩된 타깃, 디스플레이 화면비가 렌더 화면비와 다를 때의 블릿 사각형)을 거쳐 백버퍼로 옮깁니다.
- 테스트에서는 후크 함수를 직접 부르지 않고 실제 vtable 슬롯과 네이티브 생성자를 거쳐 후크에 도달합니다(07 참고).
- 한 프레임에 여러 지도 객체가 그려질 수 있습니다. 빈 객체가 방이 있는 객체를 대체하면 안 됩니다.

### 안전한 설치

- 알 수 없는 빌드는 거부합니다: 실행 파일 SHA-256, 고정 이미지 베이스, 빌드 문자열, 후킹할 모든 함수의 첫 바이트를 확인합니다. 보호된 실행 파일이 코드를 복호화할 때까지 (제한 시간과 함께) 기다립니다.
- 슬롯은 compare-and-exchange로 바꾸고, 뒤의 패치가 충돌하면 앞의 패치를 되돌립니다. 이유를 로그하고 비활성화하며 게임을 죽이지 않습니다.
- 기억해 둔 원본을 나중의 후크로 덮어쓰지 않습니다(체인 재귀). 장치 vtable마다 원본 하나. 핫 언로드는 지원하지 않습니다.
- 게임 코드에 바이트 패치를 한다면 최소한으로, 주변 바이트를 먼저 대조하고, 효과는 읽기 전용이어야 하며, 불일치하면 그 기능만 잃습니다.
- 게임 메모리는 페이지 읽기 가능 검사 후에만 읽습니다. 읽을 수 없으면 알 수 없음이며 "획득"이나 "완료"가 아닙니다.

### Present 시점 그리기

- 백버퍼에 완성된 프레임이 있는 `Present`에서 그립니다. `EndScene`은 중간 패스일 수 있습니다.
- Present가 지도 그리기보다 빠르므로 매 Present마다 최신 캡처를 계속 그립니다. 캡처를 한 번만 쓰면 깜박입니다.
- 상태 블록(전체)으로 장치 상태를 저장하고, 렌더 타깃을 지정하고, 깊이·셰이더는 없애고, 렌더·샘플러 상태 목록을 명시하고, 반 픽셀 오프셋(-0.5)의 `XYZRHW` 정점과 `SRCALPHA / INVSRCALPHA` 블렌딩을 씁니다. 끝나면 모두 복원합니다. 복원이 실패하면 오버레이를 끄고 로그합니다.
- 아이콘 연산에는 선형 밉의 아이콘 텍스처를, 글자에는 밉 없는 글자 아틀라스를 바인딩하고, 바인딩된 텍스처를 추적해 필요할 때만 상태를 바꿉니다.

### 페이드 게이트와 낡은 캡처 게이트

- 게임 화면 페이드가 올라와 있는 동안(알파가 작은 한계 초과)은 그리지 않습니다. 페이드 위에 그리면 어색합니다.
- 낡은 캡처: 매 Present마다 최신 캡처를 다시 그리므로 닫힌 지도의 마지막 캡처가 시간 창에서 벗어나기 전에 페이드가 걷히면 다시 나타납니다. 다른 모드가 페이드를 짧게 만들면 시간 창으로는 고칠 수 없습니다. **세대 래치**를 씁니다: 지도 캡처마다 증가하는 세대 번호를 주고, 매 Present에서 페이드가 올라와 있거나 지도 객체가 살아 있지 않으면 지금까지의 모든 캡처를 낡음으로 표시하며(`stale = generation`), 세대가 `stale`보다 큰 캡처만 그립니다. 페이드가 단 한 번의 Present만 올라와 있어도 옛 캡처는 다시 그려질 수 없고 그 뒤의 지도 그리기만 가능합니다. 나이 한계는 추가 보호로만 둡니다.
- 비용: 페이드 인이나 다시 열기 뒤 오버레이는 다음 지도 그리기를 기다립니다(한두 프레임).
- 처음 몇 번은 "막힘"을 로그합니다.

### 프레임(크롬) 감지

- 게임 프레임이 보이는지 추측하지 않습니다. 실게임 스프라이트 덤프에서 한 상태에만 고유한 크기의 스프라이트(보일 때만 그려지는 도움말 패널, 아이템 목록이 열려 있을 때만 그려지는 목록 띠)를 찾고, 켬/끔 상태의 스프라이트 개수로 증명하며, "2 Present 안에 보임"을 표시 중으로 봅니다.
- 배율과 오프셋은 그 스프라이트의 행렬과 렌더 사각형에서 얻습니다.

### 스프라이트 덤프 (실게임 캡처)

키 하나로 다음 한 프레임 전체에서 게임이 그리는 모든 스프라이트(객체 바이트, 뷰, 텍스처 포인터, 방, 인스턴스 id, 각 텍스처 리소스의 머리)를 임시 파일 후 교체 방식의 JSON으로 덤프합니다. 에뮬레이터를 게임과 비교하고 프레임 스프라이트를 찾는 데 씁니다.

### 32비트 게임의 텍스처와 메모리

- 프로세스 주소 공간은 약 2 GB이고 게임과 나눠 씁니다. 텍스처를 명시적으로 예산화합니다: 글자 아틀라스 4096x4096 BGRA(64 MiB)가 현실적 한계이며(생성기가 높이 4096 초과에서 예외), 아이콘은 더 작은 별도 텍스처에 두고, 파일은 정확한 크기를 확인한 뒤에만 읽고, 장치당 한 번 만들며 프레임마다 재시도하지 않습니다.
- 관리 풀 텍스처는 시스템 메모리 사본도 둘 수 있으므로 최대 두 배로 셉니다.
- 모든 실패 경로(텍스처 없음, 크기 오류, 생성·잠금 실패)를 세고 로그합니다. 아이콘은 회색 사각형으로, 이름은 생략하며 크래시하지 않습니다.

### 로그와 카운터

- 후크에서 데이터를 버리는 모든 경로에 카운터를 두고, 주기적 또는 요청 시 `Diag` 줄에 모두 출력합니다. 조용한 버림은 결함입니다.
- 새 대기 이유는 한 번만 로그하고, 상태 변화 로그는 줄 종류별 상한을 둡니다.
- 캡처 파일에는 세이브, 인벤토리, 개인정보가 없고 진행 플래그만 있습니다.

### 게이트

- 페이드: `[[0xdcbea4] + 0x20] + 0x277`(알파), 갱신 `0x5aa060`이 색을 `+0x274`에 보관. 알파가 `<= FADE_DRAW_ALPHA (64)`인 동안만 그립니다(`re0_map.c`). 읽을 수 없으면 게이트하지 않고 한 번 로그합니다.
- Present 시점의 지도 생존: 지도 객체에서 다시 읽은 vtable `0xcdc650`과 `+0x27c == 3`(`re0_map.c`). `+0x27c`는 로드되면 3, GUI 리소스가 사라질 때 `0x5b4fad`에서 4이며, 지도 그리기가 멈추기 전에 바뀌는지는 추적하지 않았으므로 닫힘 사례를 끝내는 것은 그 필드가 아니라 페이드 보류입니다.
- 래치: `re0_present_gate`(`frame.c`, 주석 `frame.h`), `overlay_allowed`(`re0_map.c`)에서 호출.
- 증상: `RE0.NoUIWait.asi`의 `FadeSpeed=3.0`에서 닫힌 지도의 마지막 캡처가 다시 그려졌습니다. 옛 게이트는 마지막 캡처가 250 ms 미만이고 페이드 알파가 64 이하이면 그렸는데, 3배 페이드에서는 창 안에 알파가 0으로 돌아왔습니다. 1배에서는 페이드 아웃이 창보다 길어 나타나지 않았습니다. 세대 래치를 추가해 고쳤습니다(NoUIWait 깜박임이 사라짐). 수정은 변이체 "fade only: stale capture drawn when a fast fade returns to clear"와 "map state ignored at Present", 시나리오 `fade_gate`, `tests/test_review48.py`(페이드 업 1, 2, 5, 60 Present 유지)로 덮습니다.
- 로그 줄: `Overlay held back: no map draw since the fade or the map is not live`(처음 8번).

### D3D 상태

`re0_map.c`: `CreateStateBlock(D3DSBT_ALL)` + `Capture`, 렌더 타깃은 백버퍼, 깊이 없음, `BeginScene`, 정점·픽셀 셰이더 끔, FVF `XYZRHW | DIFFUSE | TEX1`, Z 끔, 알파 테스트 끔, `SRCALPHA/INVSRCALPHA` 블렌드와 `BLENDOP ADD`, 컬링 없음, 라이팅·포그·스텐실·시저·sRGB 쓰기 끔, 색 쓰기 15, 색·알파 곱하기, 텍스처 스테이지 1 끔, 선형 min/mag, 밉 없음(아이콘은 선형), 클램프, 뷰포트는 백버퍼 전체. 정점은 -0.5 이동. `Apply`가 실패하면 `enabled = 0`으로 하고 `D3D state restore failed; overlay disabled`를 로그합니다. 가짜 장치로만 테스트했으며(07 참고) 밉, LOD, 상태 복원의 실제 GPU 결과는 실게임 증거만 해당합니다.

### 로그 카운터

`diag`(`re0_map.c`): maps, maps_closed, maps_empty, instances, no_context, owner_miss, id_miss, id_hit, sprites, sprite_no_context, sprite_unreadable, sprite_no_texture, sprite_alt_mode, sprite_transparent, sprite_bad_quad, sprite_room, sprite_other, flags_unreadable, layout_rejected, fade_unreadable, arrange_unreadable, arrange_mismatch, actors_unreadable, actors_overflow, rect_unreadable. 그 밖에 `icon_load_failures`, `icon_fallback_ops`, 버린 아이템 통계(`valid`, `drawn`, `unmapped`, `rejected`, `capped`; `frame.h`), 행 덤프 카운터. `Diag F8:`와 `Diag map open 2s:`로 출력합니다(`re0_map.c`). 로그 줄 상한: 게임 사각형 변화 8, 배치 표 변화 8, 페이드 게이트 변화 16, 막힘 8, 이름 확대 줄 64.

### F8 출력

`capture_report`(`re0_map.c`): schema 1 `captured-native-draw`: 프로필 해시, 지역, 타깃, 설정, 조각 상태가 있는 방 상자, 장애물 상자, 플래그 워드, `room_states` 숫자, 표 모드와 행 수, `markers_done`. `dump_write`(`re0_map.c`): schema 2 `captured-native-sprites`: 0x110바이트 스프라이트 최대 1536개, 0x80바이트 머리의 텍스처 64개. `rows_dump`(`re0_map.c`): `-rows-NN.json`, `CREATE_NEW`, 최대 32개. 캡처에는 게임의 진행 플래그가 있고 세이브 파일, 인벤토리, 개인정보는 없습니다.
